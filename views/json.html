Technical Documentation & JSON Standards

JSON (JavaScript Object Notation) is a lightweight data-interchange format that is easy for humans to read and write and easy for machines to parse and generate. It is based on a subset of the JavaScript Programming Language Standard (ECMA-262 3rd Edition). JSON is a text format that is completely language independent but uses conventions that are familiar to programmers of the C-family of languages, including C, C++, C#, Java, JavaScript, Perl, Python, and many others.

Core Structural Rules

  • Data is in name/value pairs: A name/value pair consists of a field name (in double quotes), followed by a colon, followed by a value.
  • Data is separated by commas: Commas are used to separate multiple name/value pairs or array elements.
  • Curly braces hold objects: Objects start with { and end with }.
  • Square brackets hold arrays: Arrays start with [ and end with ].

Common JSON Validation Pitfalls

While JSON is flexible, our validator enforces strict adherence to RFC 8259 to ensure compatibility across all systems. Common errors include:

  1. Single Quotes: JSON requires double quotes (") for both keys and string values. Single quotes (') will cause a syntax error.
  2. Trailing Commas: Unlike JavaScript objects, JSON does not allow a comma after the last element in an object or array.
  3. Unquoted Keys: All keys in a JSON object must be wrapped in double quotes.
  4. Control Characters: Strings must not contain unescaped control characters.

The Benefits of Key Sorting & Minification

Sorting keys alphabetically (Deterministic JSON) is essential for caching and digital signatures, as it ensures that identical objects always produce the same string representation. Minification, on the other hand, is a production-level optimization that strips all whitespace, significantly reducing the amount of data transferred over the network without affecting the data's integrity.
