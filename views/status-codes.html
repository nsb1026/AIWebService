HTTP Status Codes Reference & Troubleshooting Guide

A comprehensive developer reference of 1xx, 2xx, 3xx, 4xx, and 5xx HTTP response status codes with detailed root-cause diagnostics and frontend/backend remediation steps.

HTTP Response Status Code Categories

2xx Success (Request Successfully Received & Processed)

  • 200 OK: Standard response for successful HTTP requests. Body contains payload.
  • 201 Created: Request succeeded and a new resource was created.
  • 204 No Content: Server successfully processed request, but intentionally returns no response body.

3xx Redirection (Further Action Required)

  • 301 Moved Permanently: Target resource has been permanently assigned a new URI.
  • 302 Found (Temporary Redirect): Target resource resides temporarily under a different URI.
  • 304 Not Modified: Indicates resource has not been modified since last fetch.

4xx Client Errors (Malformed Request or Invalid Authentication)

  • 400 Bad Request: Server cannot process request due to client error.
  • 401 Unauthorized: Request requires user authentication. Missing or invalid Bearer token.
  • 403 Forbidden: Client is authenticated, but lacks permissions to access requested resource.
  • 404 Not Found: Server cannot locate requested URI route.
  • 405 Method Not Allowed: Request method (e.g. POST) is not supported for target URI.
  • 409 Conflict: Request conflicts with current state of resource.
  • 422 Unprocessable Entity: Request syntax is valid JSON, but contains semantic validation errors.
  • 429 Too Many Requests: Client has sent too many requests in a given time window (Rate Limiting).

5xx Server Errors (Server Failed to Process Request)

  • 500 Internal Server Error: Generic error message indicating server crashed.
  • 502 Bad Gateway: Server acting as gateway received invalid response from upstream server.
  • 503 Service Unavailable: Server is currently unable to handle request due to overload.
  • 504 Gateway Timeout: Server acting as gateway did not receive timely response from upstream server.
