HTTP Status Codes Reference & Troubleshooting Guide

A comprehensive developer reference of 1xx, 2xx, 3xx, 4xx, and 5xx HTTP response status codes with detailed root-cause diagnostics and frontend/backend remediation steps.

Technical Overview: HTTP status codes communicate the result of client requests to servers as standardized 3-digit integers defined by RFC 9110 (HTTP Semantics). Understanding status code semantics is essential for API integration, microservices debugging, and network error handling.

HTTP Response Status Code Categories

2xx Success (Request Successfully Received & Processed)

  • 200 OK: Standard response for successful HTTP requests. Body contains payload.
  • 201 Created: Request succeeded and a new resource was created (commonly returned by POST requests).
  • 204 No Content: Server successfully processed request, but intentionally returns no response body (commonly returned by DELETE requests).

3xx Redirection (Further Action Required)

  • 301 Moved Permanently: Target resource has been permanently assigned a new URI. Search engines transfer SEO authority.
  • 302 Found (Temporary Redirect): Target resource resides temporarily under a different URI.
  • 304 Not Modified: Indicates resource has not been modified since last fetch. Client uses browser cached version.

4xx Client Errors (Malformed Request or Invalid Authentication)

  • 400 Bad Request: Server cannot process request due to client error (e.g. malformed JSON syntax, invalid query parameter).
  • 401 Unauthorized: Request requires user authentication. Missing or invalid Bearer token or credentials.
  • 403 Forbidden: Client is authenticated, but lacks permissions to access requested resource.
  • 404 Not Found: Server cannot locate requested URI route.
  • 405 Method Not Allowed: Request method (e.g. POST) is not supported for target URI.
  • 409 Conflict: Request conflicts with current state of resource (e.g. duplicate user registration email).
  • 422 Unprocessable Entity: Request syntax is valid JSON, but contains semantic validation errors.
  • 429 Too Many Requests: Client has sent too many requests in a given time window (Rate Limiting).

5xx Server Errors (Server Failed to Process Request)

  • 500 Internal Server Error: Generic error message indicating server crashed or encountered unhandled exception.
  • 502 Bad Gateway: Server acting as gateway/proxy received invalid response from upstream application server (e.g. Nginx to Node.js / Gunicorn).
  • 503 Service Unavailable: Server is currently unable to handle request due to temporary overload or maintenance.
  • 504 Gateway Timeout: Server acting as gateway did not receive timely response from upstream server (Database or microservice timeout).

HTTP Status Code FAQ

Q: What is the difference between 401 Unauthorized and 403 Forbidden?

A: 401 Unauthorized means you are not authenticated (missing or invalid login token). 403 Forbidden means you are logged in, but your account role does not have permission to view or edit the resource.

Q: How do I fix a 502 Bad Gateway error?

A: Check if your backend app process (Node.js, Python, Java) has crashed or stopped listening on its assigned port behind Nginx/Apache proxy.
