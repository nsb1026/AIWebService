Developer Guide: Regular Expression Tokens, Flags & ReDoS Security

Regular expressions (RegEx) use a formal syntax of meta-characters and quantifiers to describe text search patterns.

1. Common Regex Token Cheatsheet

  • \d: Any digit (0-9). \D: Any non-digit.
  • \w: Word character (alphanumeric + underscore). \W: Non-word character.
  • \s: Whitespace (space, tab, newline). \S: Non-whitespace.
  • ^: Start of line. $: End of line.
  • +: 1 or more repetitions (greedy). *: 0 or more repetitions.
  • ?: 0 or 1 repetition (or makes quantifier non-greedy).

2. Standard Regex Flags

  • g (Global): Find all matches rather than stopping after the first match.
  • i (Ignore Case): Case-insensitive matching.
  • m (Multiline): ^ and $ match start/end of each line.
  • u (Unicode): Enable full Unicode pattern matching.

3. ReDoS (Regular Expression Denial of Service)

ReDoS occurs when nested quantifiers (e.g. (a+)+$) cause catastrophic backtracking on non-matching strings, causing CPU usage to hit 100% and freezing server event loops.

Prevention: Avoid overlapping nested quantifiers and set execution timeouts on regex operations.

Regex Tester FAQ

Q: Why does my regex match only the first occurrence?

A: Add the global flag g to the flags field (e.g. g or gi) to instruct the engine to scan the entire string.

Q: Is my test text sent to a remote server?

A: No. Regular expression evaluation uses native JavaScript RegExp engine execution offline.
