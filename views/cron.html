Developer Guide: Standard 5-Field Cron Syntax Breakdown

A standard Unix cron expression consists of 5 space-separated fields representing time units:

┌───────────── minute (0 - 59)
│ ┌───────────── hour (0 - 23)
│ │ ┌───────────── day of the month (1 - 31)
│ │ │ ┌───────────── month (1 - 12)
│ │ │ │ ┌───────────── day of the week (0 - 6) (Sunday to Saturday)
│ │ │ │ │
* * * * *

1. Special Characters Reference

  • * (Asterisk): Matches any value (e.g. * in month means every month).
  • , (Comma): Specifies value list (e.g. 1,15,30 in minute field).
  • - (Hyphen): Defines value range (e.g. 1-5 in day-of-week for Mon-Fri).
  • / (Slash): Specifies step increments (e.g. */10 in minute means every 10 minutes).

2. Server Timezone Caution

Cron schedules execute according to the host system's local server time or UTC setting. Always confirm whether your cloud provider (AWS, GCP, Vercel) runs on UTC or local server time when configuring scheduled jobs.

3. Kubernetes & CI/CD Pipelines

Kubernetes CronJob manifests and GitHub Actions on.schedule.cron use 5-part cron syntax. GitHub Actions enforces a minimum interval of 5 minutes to prevent job queue congestion.

Cron Explainer FAQ

Q: Is day 0 Sunday or Monday in Cron?

A: Day 0 (and Day 7 in extended cron) represents Sunday. 1 represents Monday, 2 Tuesday, through 6 Saturday.

Q: How do I run a task every 5 minutes?

A: Use */5 * * * *. The */5 in the minute position specifies a step value of 5.
